# 仕様作成スキル (Specification Authoring Skill)

このスキルは、要件定義で決まった内容を開発者が実装・設計へ移せるレベルの緻密な「仕様」へと落とし込む手順を提供します。

---

## 主な仕様策定項目

### 1. データモデル / データベーススキーマ仕様
- エンティティ定義、リレーションシップ (1:1, 1:N, N:M)
- 各フィールドの型、NULL可否、デフォルト値、制約条件

### 2. API / インターフェース仕様
- エンドポイント (REST / GraphQL / RPC)
- リクエストパラメータ / ヘッダー / ボディフォーマット
- レスポンスフォーマット (成功時・エラー時)
- エラーハンドリング仕様 (HTTPステータスコード、エラーコード定義)

### 3. UI / 画面仕様 (Web/App の場合)
- 画面一覧と画面遷移図
- 画面ごとの構成要素・表示項目・入力項目
- バリデーションルール (フロントエンド/バックエンド)

### 4. ビジネスロジック / 状態遷移仕様
- ステートマシン / 状態遷移図 (例: 未決済 -> 決済済み -> 発送完了)
- ドメインルールの明確化

---

## 仕様書テンプレート (`docs/specifications.md`)

```markdown
# 仕様書: [プロジェクト名]

## 1. データモデル仕様
### [EntityName]
| フィールド名 | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| id | String/UUID | Yes | 識別子 |
| created_at | DateTime | Yes | 作成日時 |

## 2. API 仕様
### `POST /api/v1/resource`
- **概要**: 
- **リクエスト**:
```json
{
  "key": "value"
}
```
- **レスポンス (201 Created)**:
```json
{
  "id": "123",
  "status": "success"
}
```

## 3. 画面遷移・画面仕様
- **画面A (ホーム)** -> [ボタンクリック] -> **画面B (詳細)**

## 4. ビジネスロジック・例外処理
- バリデーションエラー発生時は `400 Bad Request` を返却する。
```
